# 从 C++ 到 Python：Ray 的跨语言绑定机制

## 示例：FunctionDescriptor 的全链路追踪

以 `FunctionDescriptor` 为例，追踪一个类型从 `.proto` 定义 → C++ 实现 → Cython 绑定 → Python 使用 的完整链路。

### 1. Protobuf 定义（数据层起点）

[common.proto:134-164](src/ray/protobuf/common.proto#L134-L164) 定义了三种语言的函数描述符消息和联合类型包装：

```protobuf
message JavaFunctionDescriptor {
  string class_name = 1;
  string function_name = 2;
  string signature = 3;
}

message PythonFunctionDescriptor {
  string module_name = 1;
  string class_name = 2;
  string function_name = 3;
  string function_hash = 4;
}

message CppFunctionDescriptor {
  string function_name = 1;
  string caller = 2;
  string class_name = 3;
}

message FunctionDescriptor {
  oneof function_descriptor {
    JavaFunctionDescriptor java_function_descriptor = 1;
    PythonFunctionDescriptor python_function_descriptor = 2;
    CppFunctionDescriptor cpp_function_descriptor = 3;
  }
}
```

Bazel 通过 `//src/ray/protobuf:common_cc_proto` 目标（[BUILD.bazel:20-23](src/ray/protobuf/BUILD.bazel#L20-L23)）从 `.proto` 生成 C++ 类 `rpc::FunctionDescriptor`、`rpc::PythonFunctionDescriptor` 等。

### 2. C++ 实现（业务逻辑层）

[function_descriptor.h](src/ray/common/function_descriptor.h) 定义了继承体系，以 protobuf 消息作为底层数据存储：

- `FunctionDescriptorInterface` — 基类，继承 `MessageWrapper<rpc::FunctionDescriptor>`（来自 [grpc_util.h](src/ray/common/grpc_util.h)），持有 protobuf 消息对象
- `EmptyFunctionDescriptor` / `JavaFunctionDescriptor` / `PythonFunctionDescriptor` / `CppFunctionDescriptor` — 各语言的子类，通过 `typed_message_` 指针直接访问 protobuf `oneof` 中的对应字段
- `FunctionDescriptorBuilder` — 工厂类，通过 `BuildPython()`、`FromProto()`、`Deserialize()` 等方法构造具体子类
- `typedef std::shared_ptr<FunctionDescriptorInterface> FunctionDescriptor` — 统一对外类型

[function_descriptor.cc](src/ray/common/function_descriptor.cc) 实现工厂方法，例如 `BuildPython`：

```cpp
FunctionDescriptor FunctionDescriptorBuilder::BuildPython(
    const std::string &module_name,
    const std::string &class_name,
    const std::string &function_name,
    const std::string &function_hash) {
  rpc::FunctionDescriptor descriptor;                          // 创建 protobuf 消息
  auto typed = descriptor.mutable_python_function_descriptor(); // 设置 oneof 字段
  typed->set_module_name(module_name);
  typed->set_class_name(class_name);
  typed->set_function_name(function_name);
  typed->set_function_hash(function_hash);
  return ray::FunctionDescriptor(new PythonFunctionDescriptor(std::move(descriptor)));
}
```

编译规则（[BUILD.bazel:188-198](src/ray/common/BUILD.bazel#L188-L198)）：

```bazel
ray_cc_library(
    name = "function_descriptor",
    srcs = ["function_descriptor.cc"],
    hdrs = ["function_descriptor.h"],
    deps = [
        ":grpc_util",                            # MessageWrapper 基类
        "//src/ray/protobuf:common_cc_proto",     # 生成的 protobuf C++ 类
        "//src/ray/util:logging",                 # RAY_CHECK / RAY_LOG
        "@com_google_absl//absl/strings:str_format", # absl::StrFormat
    ],
)
```

`ray_cc_library` 是 [ray.bzl:138](bazel/ray.bzl#L138) 定义的宏，在原生 `cc_library` 上附加 `strip_include_prefix="/src"` 和统一 `COPTS`。

### 3. Cython 声明层（.pxd — C++ 接口映射）

[function_descriptor.pxd](python/ray/includes/function_descriptor.pxd) 用 `cdef extern from` 将 C++ 类映射为 Cython 可识别的类型：

```cython
# 引入 protobuf 生成的 C++ 头中的枚举
cdef extern from "src/ray/protobuf/common.pb.h" nogil:
    cdef cppclass CFunctionDescriptorType "ray::FunctionDescriptorType": pass
    cdef CFunctionDescriptorType EmptyFunctionDescriptorType \
        "ray::FunctionDescriptorType::FUNCTION_DESCRIPTOR_NOT_SET"
    cdef CFunctionDescriptorType PythonFunctionDescriptorType \
        "ray::FunctionDescriptorType::kPythonFunctionDescriptor"
    ...

# 引入 function_descriptor.h 中的 C++ 类
cdef extern from "ray/common/function_descriptor.h" nogil:
    cdef cppclass CFunctionDescriptorInterface "ray::FunctionDescriptorInterface":
        CFunctionDescriptorType Type()
        c_string ToString()

    ctypedef shared_ptr[CFunctionDescriptorInterface] CFunctionDescriptor \
        "ray::FunctionDescriptor"

    cdef cppclass CFunctionDescriptorBuilder "ray::FunctionDescriptorBuilder":
        @staticmethod
        CFunctionDescriptor BuildPython(const c_string &module_name,
                                        const c_string &class_name,
                                        const c_string &function_name,
                                        const c_string &function_source_hash)
        ...

    cdef cppclass CPythonFunctionDescriptor "ray::PythonFunctionDescriptor":
        c_string ModuleName()
        c_string ClassName()
        c_string FunctionName()
        c_string FunctionHash()
```

关键机制：**字符串别名映射**。`"ray::PythonFunctionDescriptor"` 是 C++ 中的真实类名，`CPythonFunctionDescriptor` 是 Cython 侧的标识符。Cython 编译器生成 C++ 代码时会用真实类名替换。

### 4. Cython 实现层（.pxi — Python 包装类）

[function_descriptor.pxi](python/ray/includes/function_descriptor.pxi) 定义 Python 可使用的类，内部持有 C++ 对象指针：

```cython
cdef class FunctionDescriptor:              # Python 基类
    def __hash__(self):
        return hash(self.descriptor.get().ToString())   # 调用 C++ 方法

    def __eq__(self, other):
        return self.descriptor.get().ToString() == \
               (<FunctionDescriptor>other).descriptor.get().ToString()

cdef class PythonFunctionDescriptor(FunctionDescriptor):
    cdef CPythonFunctionDescriptor *typed_descriptor   # 指向 C++ 子类的指针

    def __cinit__(self, module_name, function_name, class_name="", function_source_hash=""):
        # 通过 C++ 工厂方法构造底层对象
        self.descriptor = CFunctionDescriptorBuilder.BuildPython(
            module_name, class_name, function_name, function_source_hash)
        self.typed_descriptor = <CPythonFunctionDescriptor*>(self.descriptor.get())

    @property
    def module_name(self):
        return <str>self.typed_descriptor.ModuleName()   # C++ → Python 字符串转换

    @classmethod
    def from_function(cls, function, function_uuid):
        """从 Python 函数对象构造描述符"""
        module_name = cls._get_module_name(function)
        function_name = function.__qualname__
        return cls(module_name, function_name, "", function_uuid.hex)

    def _get_function_id(self):
        """用 shake_128 哈希计算函数 ID"""
        function_id_hash = hashlib.shake_128()
        function_id_hash.update(self.typed_descriptor.ModuleName())
        function_id_hash.update(self.typed_descriptor.FunctionName())
        function_id_hash.update(self.typed_descriptor.ClassName())
        function_id_hash.update(self.typed_descriptor.FunctionHash())
        return ray.FunctionID(function_id_hash.digest(ray_constants.ID_SIZE))
```

还有从 C++ 到 Python 的反向桥接：

```cython
ctypedef object (*FunctionDescriptor_from_cpp)(const CFunctionDescriptor &)
cdef unordered_map[int, FunctionDescriptor_from_cpp] FunctionDescriptor_constructor_map

cdef CFunctionDescriptorToPython(CFunctionDescriptor function_descriptor):
    """根据 C++ 对象的类型枚举值，查表找到对应的 Python 构造函数"""
    cdef int type = <int>function_descriptor.get().Type()
    constructor = FunctionDescriptor_constructor_map[type]
    return constructor(function_descriptor)

# 注册每种类型的构造函数
FunctionDescriptor_constructor_map[<int>PythonFunctionDescriptorType] = \
    PythonFunctionDescriptor.from_cpp
```

当 C++ core_worker 返回一个 `ray::FunctionDescriptor` 给 Python 时，通过 `CFunctionDescriptorToPython()` 查表自动转换为对应的 Python 子类实例。

### 5. Cython 汇编层（_raylet.pyx — 模块入口）

[_raylet.pyx:184](python/ray/_raylet.pyx#L184) 通过 `include` 指令将 `.pxi` 文件并入模块：

```cython

```

这使得 `PythonFunctionDescriptor` 等类成为 `_raylet` 模块的导出成员。

### 6. Bazel 编译（Cython → 共享库）

[BUILD.bazel:152-201](BUILD.bazel#L152-L201) 中 `pyx_library` 规则编译 `_raylet`：

```bazel
pyx_library(
    name = "_raylet",
    srcs = glob([
        "python/ray/includes/*.pxd",    # 所有 .pxd 声明文件
        "python/ray/includes/*.pxi",    # 所有 .pxi 实现文件
    ]) + [
        "python/ray/_raylet.pyx",       # 主 Cython 模块
    ],
    deps = [
        "//src/ray/core_worker:core_worker_lib",  # 传递依赖包含 function_descriptor
        "//src/ray/protobuf:serialization_cc_proto", # protobuf 序列化
        ...
    ],
)
```

编译流程：Cython 编译器将 `.pyx` + `.pxi` → `.cpp`，然后 C++ 编译器将生成的 `.cpp` 与 `deps` 中的 C++ 库链接，产出 `_raylet.so`（macOS）或 `_raylet.pyd`（Windows）。

依赖传递路径：`_raylet` → `core_worker_lib` → ... → `//src/ray/common:function_descriptor` → `//src/ray/protobuf:common_cc_proto`。

### 7. Python 使用层（remote_function.py）

[remote_function.py:20-24](python/ray/remote_function.py#L20-L24) 从编译好的 `_raylet` 模块导入：

```python
from ray._raylet import (
    STREAMING_GENERATOR_RETURN,
    ObjectRefGenerator,
    PythonFunctionDescriptor,    # ← Cython 包装类
)
```

在 [remote_function.py:354-356](python/ray/remote_function.py#L354-L356)，任务首次提交时构造描述符：

```python
self._function_descriptor = PythonFunctionDescriptor.from_function(
    self._function, self._uuid
)
# from_function 内部：
#   module_name = cls._get_module_name(function)  → e.g. "__main__"
#   function_name = function.__qualname__          → e.g. "my_func"
#   return cls(module_name, function_name, "", function_uuid.hex)
# cls() 的 __cinit__ 调用 CFunctionDescriptorBuilder.BuildPython()
#   → C++ 创建 rpc::FunctionDescriptor protobuf 消息
```

在 [remote_function.py:491-509](python/ray/remote_function.py#L491-L509)，将描述符传入 core_worker 提交任务：

```python
object_refs = worker.core_worker.submit_task(
    self._language,
    self._function_descriptor,     # PythonFunctionDescriptor 实例
    list_args,                     # ↓ Cython 自动将 Python 对象转为 C++ shared_ptr
    ...
)
```

`submit_task` 是 `_raylet.pyx` 中定义的 Cython 方法，接收 `PythonFunctionDescriptor` 参数时，通过 `.descriptor`（`CFunctionDescriptor`，即 `shared_ptr<CFunctionDescriptorInterface>`）直接传递 C++ 对象给 `CoreWorker::SubmitTask()`。

属性访问（如 [remote_function.py:456](python/ray/remote_function.py#L456) 的 `.function_name`）走 Cython property → `typed_descriptor->FunctionName()` → C++ 方法 → protobuf 字段。

### 关键设计要点

1. **Protobuf 作为跨语言数据格式**：C++ 类以 `rpc::FunctionDescriptor` protobuf 消息为底层数据（通过 `MessageWrapper`），序列化/反序列化天然支持，Python/C++/Java 三端共享同一消息定义。

2. **Cython 字符串别名**：`.pxd` 中 `"ray::PythonFunctionDescriptor"` 语法让 Cython 用自定义标识符（`CPythonFunctionDescriptor`）映射到 C++ 真实类名，避免命名冲突。

3. **双向桥接**：Python → C++ 通过 `__cinit__` 调用 `CFunctionDescriptorBuilder`；C++ → Python 通过 `CFunctionDescriptorToPython()` 查 `constructor_map` 表自动选择子类。

4. **属性零拷贝语义**：Cython property（如 `.module_name`）直接调用 C++ 方法返回 `const string&`，Cython 做 `<str>` 转换为 Python 字符串，不需要在 Python 层维护额外副本。

5. **`from_function` 是纯 Python 逻辑**：提取 `__module__`、`__qualname__` 后调用 Cython 构造函数，Cython 构造函数再调用 C++ 工厂方法——每一层只做自己擅长的部分。
