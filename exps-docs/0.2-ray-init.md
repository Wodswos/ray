# ray.init() 与 connect() 流程分析

## 总览

`ray.init()` 是用户入口（PublicAPI），负责"要不要建集群 + 准备环境 + 委托连接"。
`connect()` 是内部函数，负责"建立与 Ray 核心服务的实际连接通道"。

调用链：`ray.init()` → 创建/连接 Node → `connect()` → 创建 CoreWorker → 标记 connected

---

## ray.init() 详细流程

### 1. 日志 & 环境准备
- 配置 ray logger（level / format / logging_config）
- 解析隐藏参数（`_system_config`, `_plasma_directory`, `_node_ip_address` 等）
- 设置 SIGTERM handler（主线程中）
- 尝试提升文件描述符上限（RLIMIT_NOFILE → 65536）

### 2. 地址解析 & 集群决策
- `address` 参数或 `RAY_ADDRESS` 环境变量 → `canonicalize_bootstrap_address()`
- 若地址含协议（如 `ray://`）→ 走 **Ray Client** 路径，返回 `ClientContext`
- `bootstrap_address` 为 None → **新建集群**
- `bootstrap_address` 有值 → **连接已有集群**

### 3. JobConfig & Runtime Env 处理
- 合并 `RAY_JOB_CONFIG_JSON_ENV_VAR` 环境变量注入的 job config
- `_merge_runtime_env()` 合入 driver 传入的 runtime_env（冲突时可用 `RAY_OVERRIDE_JOB_RUNTIME_ENV=1`）
- `_maybe_modify_runtime_env()` 执行 env hook
- 将 `logging_config` 写入 job_config

### 4. 新建集群路径（bootstrap_address == None）
- `ensure_token_if_auth_enabled(..., create_token_if_missing=True)` 创建认证 token
- usage stats 处理（nightly wheel 才收集）
- 构建 `RayParams`（包含 num_cpus/gpus/resources/dashboard/object_store_memory 等全部参数）
- 创建 `_global_node = Node(ray_params, head=True, spawn_reaper=True, ray_init_cluster=True)`
  - Node 内部启动 raylet / GCS / dashboard / Plasma 等进程

### 5. 连接已有集群路径（bootstrap_address != None）
- 校验：num_cpus/gpus/resources/labels/object_store_memory/_system_config/_node_name 不允许传入
- `ensure_token_if_auth_enabled(..., create_token_if_missing=False)` 仅验证 token
- 构建 `RayParams`（仅含 gcs_address / temp_dir 等）
- `_global_node = Node(ray_params, head=False, connect_only=True)`
  - Node 不启动任何进程，仅记录集群信息

### 6. Dashboard URL 处理
- 支持 `RAY_OVERRIDE_DASHBOARD_URL` 环境变量覆盖
- 自动补 `http://` 协议前缀

### 7. 调用 connect()
```python
connect(
    _global_node,
    _global_node.session_name,
    mode=driver_mode,        # SCRIPT_MODE 或 LOCAL_MODE
    log_to_driver=log_to_driver,
    worker=global_worker,
    driver_object_store_memory=_driver_object_store_memory,
    job_id=None,             # driver 模式下由 connect 内部生成
    namespace=namespace,
    job_config=job_config,
    entrypoint=ray._private.utils.get_entrypoint_name(),
)
```

### 8. init 后续
- 设置 `load_code_from_local` 标志
- 运行 `_post_init_hooks`
- 显示 accelerator override 警告
- 返回 `RayContext(dict(address_info, node_id=node_id.hex()))`

## connect() 详细流程

### 1. 基础校验
- `assert not worker.connected` — 防止重复连接
- 启用 `faulthandler`（SIGSEGV 等信号打出 stack trace）

### 2. GCS 连接 & 全局状态初始化
- `worker.gcs_client = node.get_gcs_client()` — 获取 GCS client
- `_initialize_internal_kv(gcs_client)` — 初始化内部 KV 存储
- `state._initialize_global_state(GcsClientOptions(...))` — 初始化全局状态（cluster_id 等）

### 3. Job ID 处理
- WORKER_MODE / RESTORE_WORKER_MODE / SPILL_WORKER_MODE → `JobID.nil()`（由 raylet 后续分配）
- DRIVER / SCRIPT / LOCAL 模式 → 若 job_id 为 None，调用 `next_job_id()` 生成

### 4. 进程名 & 模式设置
- worker 模式 → `setproctitle(WORKER_PROCESS_TYPE_IDLE_WORKER / SPILL / RESTORE)`
- `worker.node = node`, `worker.set_mode(mode)`

### 5. 版本兼容性检查
- `node.check_version_info()` — 对比当前版本与集群启动版本
- SCRIPT_MODE → 不匹配直接 raise
- WORKER_MODE → 不匹配 publish error 到 driver

### 6. Driver 信息收集
- SCRIPT_MODE → 从 `__main__.__file__` 获取 driver_name，否则标记 `interactive_mode=True`
- 非 SCRIPT / LOCAL → raise ValueError

### 7. JobConfig & Namespace
- job_config 缺省 → `JobConfig()`
- namespace 非空 → `validate_namespace()` + `job_config.set_ray_namespace()`

### 8. PYTHONBREAKPOINT 设置
- WORKER_MODE → `"ray.util.rpdb.set_trace"`
- Driver → `"ray.util.rpdb._driver_set_trace"`

### 9. Runtime Env 上传（仅 SCRIPT_MODE 非 ray_client）
- `upload_py_modules_if_needed()` — 打包上传 py_modules
- `upload_working_dir_if_needed()` — 打包上传 working_dir
- `upload_worker_process_setup_hook_if_needed()` — 打包 setup hook
- 移除 `excludes` 字段（上传后不再需要）
- `job_config.set_runtime_env(runtime_env, validate=True)` — 更新 job_config

### 10. Driver sys.path 扩展（仅 SCRIPT_MODE）
- 添加脚本所在目录（若 `sys.path` 中包含它）
- 添加当前工作目录（非 client 且非 working_dir 时）
- 写入 `job_config._py_driver_sys_path`

### 11. 创建 CoreWorker（C++ 层核心对象）
```python
worker.core_worker = ray._raylet.CoreWorker(
    mode,
    node.plasma_store_socket_name,  # Plasma 对象存储 socket
    node.raylet_socket_name,         # Raylet socket
    job_id,
    gcs_options,
    logs_dir,
    node.node_ip_address,
    node.node_manager_port,
    (mode == LOCAL_MODE),            # local_mode 标志
    driver_name,
    serialized_job_config,
    node.metrics_agent_port,
    runtime_env_hash,
    startup_token,
    session_name,
    node.cluster_id.hex(),
    entrypoint,                      # 仅 SCRIPT_MODE 传入
    worker_launch_time_ms,
    worker_launched_time_ms,
    debug_source,
)
```
CoreWorker 是 C++ 实现的对象，负责：
- 连接 raylet（任务调度与资源管理）
- 连接 Plasma（对象存储与共享内存）
- 注册到 GCS（作业与 actor 管理）

### 12. Error & Log 订阅（仅 SCRIPT_MODE）
- 创建 `GcsErrorSubscriber` / `GcsLogSubscriber`
- 启动 `listener_thread`（后台轮询 error messages）
- 若 `log_to_driver=True` → 启动 `logger_thread`（后台打印 worker 日志）

### 13. Tracing 设置
- 从 internal KV 读取 `tracing_startup_hook`
- 若存在 → `_enable_tracing()` + `_setup_tracing()`

### 14. 标记完成
- `worker.set_is_connected(True)` — 标记连接完成

## 职责对比

| 维度 | ray.init() | connect() |
|------|-----------|----------|
| **调用者** | 用户代码 `ray.init(...)` | init() 或 raylet 启动 worker 进程 |
| **核心职责** | 集群生命周期管理（新建/连接） | 服务通道建立（GCS/Plasma/Raylet） |
| **是否创建 Node** | 是（决定 head 或 worker） | 否，接收已有 Node |
| **是否创建 CoreWorker** | 否（委托 connect） | 是 |
| **Runtime Env 处理** | 合并/修改 env，写入 job_config | 上传文件到集群，更新 job_config |
| **参数风格** | 用户友好（num_cpus/dashboard 等） | 内部细节（job_id/startup_token 等） |
| **返回值** | RayContext / ClientContext | 无（修改 worker 状态） |

**一句话总结**：`init` 管"要不要建集群"，`connect` 管"怎么连上服务"。
